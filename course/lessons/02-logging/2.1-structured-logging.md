## 📚 Why Structured Logging?

### The Problem with Basic Logging

Many beginners start with simple `Write-Host` commands:

```powershell
# ❌ Basic, unstructured logging
Write-Host "Starting process"
Write-Host "Error: File not found"
Write-Host "Process complete"
```

**Problems:**
- No timestamps - when did it happen?
- No severity - is this an error or just info?
- No context - which line of code?
- No color coding - hard to scan
- Can't be parsed by tools
- Can't easily filter by level

### The Solution: Structured Logging

```powershell
# ✅ Structured logging with Write-Detail
Write-Detail "Starting process" -Level Info
Write-Detail "File not found: config.json" -Level Error
Write-Detail "Process completed successfully" -Level Success
```

**Benefits:**
- ✅ Automatic timestamps
- ✅ Severity levels
- ✅ Line numbers for debugging
- ✅ Color-coded output
- ✅ Consistent format
- ✅ Parseable and filterable

**Output:**
```
2026-03-29 14:30:15 [INFO] Line 42: Starting process
2026-03-29 14:30:16 [ERROR] Line 58: File not found: config.json
2026-03-29 14:30:18 [SUCCESS] Line 75: Process completed successfully
```

## 🔍 The Write-Detail Function

### Implementation

Open: `Add-WeektoSignature.ps1` line 150-180

```powershell
Function Write-Detail {
    <#
    .SYNOPSIS
        Writes detailed log messages with timestamp, level, and line number
    #>
    param(
        [Parameter(Mandatory = $true)]
        [string]$Message,

        [ValidateSet('Info', 'Warning', 'Error', 'Debug', 'Success')]
        [string]$Level = 'Info',

        [string]$LogFile = $null
    )

    # Get timestamp and caller information
    $timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
    $caller = (Get-PSCallStack)[1]
    $lineNumber = $caller.ScriptLineNumber

    # Build the log entry
    $logEntry = "$timestamp [$Level] Line $lineNumber: $Message"

    # Color-coded console output
    switch ($Level) {
        'Error'   { Write-Host $logEntry -ForegroundColor White -BackgroundColor Red }
        'Warning' { Write-Host $logEntry -ForegroundColor Black -BackgroundColor Yellow }
        'Success' { Write-Host $logEntry -ForegroundColor Green }
        'Debug'   { Write-Host $logEntry -ForegroundColor Gray }
        default   { Write-Host $logEntry }
    }

    # Optional file logging
    if ($LogFile) {
        Add-Content -Path $LogFile -Value $logEntry
    }
}
```

### Breaking It Down

#### 1. Parameters

```powershell
[Parameter(Mandatory = $true)]
[string]$Message
```
- `Mandatory = $true` - Must provide a message
- Empty strings will cause an error (by design!)

```powershell
[ValidateSet('Info', 'Warning', 'Error', 'Debug', 'Success')]
[string]$Level = 'Info'
```
- `ValidateSet` - Only allows these 5 values
- Typos like 'Erorr' will be caught immediately
- Default is 'Info' if not specified

```powershell
[string]$LogFile = $null
```
- Optional file logging
- If provided, writes to file in addition to console

#### 2. Timestamp

```powershell
$timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss"
```
- Format: 2026-03-29 14:30:15
- ISO-8601 style (sortable, parseable)
- Consistent across all log entries

#### 3. Call Stack Magic

```powershell
$caller = (Get-PSCallStack)[1]
$lineNumber = $caller.ScriptLineNumber
```

**What's happening:**
- `Get-PSCallStack` returns the current call stack
- `[1]` gets the caller (not Write-Detail itself, but who called it)
- `.ScriptLineNumber` gives the line number where Write-Detail was called

**Why this is powerful:**
You get automatic line numbers without manually specifying them!

```powershell
Write-Detail "Processing item" -Level Info  # Line 42
# Output: 2026-03-29 14:30:15 [INFO] Line 42: Processing item
```

#### 4. Color Coding

```powershell
switch ($Level) {
    'Error'   { Write-Host $logEntry -ForegroundColor White -BackgroundColor Red }
    'Warning' { Write-Host $logEntry -ForegroundColor Black -BackgroundColor Yellow }
    'Success' { Write-Host $logEntry -ForegroundColor Green }
    'Debug'   { Write-Host $logEntry -ForegroundColor Gray }
    default   { Write-Host $logEntry }
}
```

- **Error:** White text on red background (impossible to miss!)
- **Warning:** Black text on yellow background (caution)
- **Success:** Green text (positive feedback)
- **Debug:** Gray text (low visibility for noise)
- **Info:** Default colors (normal operation)

## 💻 Log Levels Explained

### When to Use Each Level

#### Info - Normal Operations
Use for: Regular flow of execution, state changes, milestones

```powershell
Write-Detail "Application starting..." -Level Info
Write-Detail "Loading configuration from: $configPath" -Level Info
Write-Detail "Connected to database" -Level Info
Write-Detail "Processing 50 records" -Level Info
```

#### Success - Positive Outcomes
Use for: Successful completion, confirmations

```powershell
Write-Detail "File saved successfully: $fileName" -Level Success
Write-Detail "All tests passed" -Level Success
Write-Detail "Signature updated" -Level Success
```

#### Warning - Potential Issues
Use for: Non-critical problems, deprecations, fallbacks

```powershell
Write-Detail "Config file not found, using defaults" -Level Warning
Write-Detail "API response took 5 seconds (slow)" -Level Warning
Write-Detail "Retry attempt 2 of 3" -Level Warning
```

#### Error - Failures
Use for: Exceptions, failures, critical problems

```powershell
Write-Detail "Failed to connect to database: $($_.Exception.Message)" -Level Error
Write-Detail "File not found: $filePath" -Level Error
Write-Detail "API returned status 500" -Level Error
```

#### Debug - Verbose Details
Use for: Detailed diagnostic information, variable values

```powershell
Write-Detail "Variable value: count=$count, total=$total" -Level Debug
Write-Detail "Entering function: Process-Item" -Level Debug
Write-Detail "Query result: $($result | ConvertTo-Json -Compress)" -Level Debug
```

## 🎨 Real-World Examples

### Example 1: API Call Logging

From `Upload-ToLiquidFiles.ps1`:

```powershell
try {
    Write-Detail "Connecting to LiquidFiles API: $serverUrl" -Level Info

    $response = Invoke-RestMethod `
        -Uri $url `
        -Method POST `
        -Headers $headers `
        -Body $body `
        -ErrorAction Stop

    Write-Detail "API request successful, message ID: $($response.id)" -Level Success
}
catch {
    Write-Detail "API request failed: $($_.Exception.Message)" -Level Error
    Write-Detail "Stack trace: $($_.ScriptStackTrace)" -Level Debug
    throw
}
```

### Example 2: File Operations

```powershell
Write-Detail "Searching for signature files in: $signaturePath" -Level Info

if (-not (Test-Path $signaturePath)) {
    Write-Detail "Signature directory not found, creating: $signaturePath" -Level Warning
    New-Item -ItemType Directory -Path $signaturePath | Out-Null
}

$files = Get-ChildItem -Path $signaturePath -Filter "*.htm"
Write-Detail "Found $($files.Count) signature files" -Level Info

foreach ($file in $files) {
    Write-Detail "Processing: $($file.Name)" -Level Debug

    try {
        $content = Get-Content $file.FullName -Raw
        Write-Detail "Loaded file: $($file.Name) ($($content.Length) bytes)" -Level Success
    }
    catch {
        Write-Detail "Failed to load: $($file.Name) - $($_.Exception.Message)" -Level Error
    }
}
```

### Example 3: Progress Tracking

```powershell
$items = 1..100

Write-Detail "Starting batch process: $($items.Count) items" -Level Info

$successCount = 0
$failCount = 0

foreach ($item in $items) {
    Write-Detail "Processing item $item of $($items.Count)" -Level Debug

    try {
        Process-Item $item
        $successCount++

        if ($item % 10 -eq 0) {
            Write-Detail "Progress: $item/$($items.Count) complete" -Level Info
        }
    }
    catch {
        $failCount++
        Write-Detail "Item $item failed: $($_.Exception.Message)" -Level Warning
    }
}

Write-Detail "Batch complete: $successCount succeeded, $failCount failed" -Level Success
```

## ⚠️ Important: Don't Use Write-Detail With Empty Strings

**This will fail:**
```powershell
Write-Detail ""  # ❌ ERROR: Mandatory parameter cannot be empty
```

**Instead, use Write-Host for blank lines:**
```powershell
Write-Detail "Section 1 complete" -Level Info
Write-Host ""  # ✅ Blank line
Write-Detail "Starting Section 2" -Level Info
```

**For repeated characters (like separators):**
```powershell
Write-Detail ("=" * 80) -Level Info  # ✅ Use parentheses to evaluate expression
```

**Not this:**
```powershell
Write-Detail "=" * 80  # ❌ Sends literal string "= * 80", doesn't multiply
```

## ✅ Knowledge Check

### Question 1
Which log level should you use when a config file is missing but the script can use defaults?

<details>
<summary>Show Answer</summary>

**Warning** - The situation is not ideal (missing config) but not fatal (can continue with defaults). This alerts the user but doesn't indicate failure.

```powershell
Write-Detail "Config file not found, using default settings" -Level Warning
```

</details>

### Question 2
Why do we use `Get-PSCallStack` instead of hardcoding line numbers?

<details>
<summary>Show Answer</summary>

**Automatic accuracy** - Line numbers update automatically as code changes. If you hardcode them, they become wrong after edits. `Get-PSCallStack` always reports the correct line number where Write-Detail was called.

</details>

### Question 3
What's wrong with this?

```powershell
Write-Detail "Processing items..." -Level Info
Write-Detail ""
Write-Detail "Done!" -Level Success
```

<details>
<summary>Show Answer</summary>

Line 2: `Write-Detail ""` will fail because Message is mandatory and cannot be empty.

**Fix:**
```powershell
Write-Detail "Processing items..." -Level Info
Write-Host ""  # Use Write-Host for blank lines
Write-Detail "Done!" -Level Success
```

</details>

## 🎓 Key Takeaways

✅ **Structured logging** is essential for maintainable scripts
✅ **Write-Detail** provides timestamps, levels, and line numbers automatically
✅ **Five log levels**: Info, Success, Warning, Error, Debug
✅ **Color coding** makes logs scannable at a glance
✅ **Call stack** gives automatic line numbers for debugging
✅ **Never use empty strings** with Write-Detail (use Write-Host instead)
✅ **Consistency** across all scripts makes troubleshooting easier
