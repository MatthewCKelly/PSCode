## 📚 Core Concepts

### The WebBrowser Control

The `System.Windows.Forms.WebBrowser` control is an embedded Internet Explorer/Edge browser that you can place in your Windows Forms applications. It's perfect for:

- Displaying formatted HTML content
- Previewing email signatures (like in our Signature Manager!)
- Showing help documentation
- Rendering rich text with styles
- Displaying web-based reports

**Key Properties:**
- `DocumentText` - Get/set the HTML content
- `Document` - Access the DOM (Document Object Model)
- `ScriptErrorsSuppressed` - Hide JavaScript errors
- `AllowWebBrowserDrop` - Enable/disable drag-drop
- `ScrollBarsEnabled` - Show/hide scrollbars

**Key Events:**
- `DocumentCompleted` - Fires when page finishes loading
- `Navigating` - Fires before navigation starts
- `DocumentTitleChanged` - Fires when title changes

## 🚨 The Critical Bug & Fix

### The Problem

When the Signature Manager first loaded, the HTML preview showed only `<HTML></HTML>` - a blank page! But after changing any dropdown, it suddenly worked.

**Why?**

The WebBrowser control wasn't fully initialized when we tried to set `DocumentText`.

### The Original (Broken) Code

```powershell
# Line 2579 (OLD)
& $updatePreview  # Called immediately after creating controls

# Inside $updatePreview (line 2005):
$previewBrowser.DocumentText = $previewHTML  # ❌ Fails silently!
```

**The issue:** The WebBrowser's internal DOM wasn't created yet, so setting `DocumentText` had no effect.

### The Fix (Current Code)

**Step 1: Initialize the DOM** (line 1831)
```powershell
# Initialize the WebBrowser control's document
# This ensures the control is ready to accept DocumentText immediately
$previewBrowser.Navigate("about:blank")
```

**What's happening:**
- `Navigate("about:blank")` forces the browser to create its DOM
- "about:blank" is a special URL that loads instantly (no network)
- This is **asynchronous** - returns immediately, but DOM loads in background

**Step 2: Wait for Initialization** (line 2582-2592)
```powershell
# Add a one-time event handler for when WebBrowser finishes initializing
$script:initialPreviewDone = $false

$previewBrowser.Add_DocumentCompleted({
    param($sender, $e)

    if (-not $script:initialPreviewDone) {
        $script:initialPreviewDone = $true
        Write-Detail -Message "WebBrowser initialized, showing initial preview" -Level Debug
        & $updatePreview
    }
})
```

**Breaking down the event handler:**

1. **Flag to track state:**
   ```powershell
   $script:initialPreviewDone = $false
   ```
   - Prevents running the handler multiple times
   - `$script:` scope makes it accessible everywhere

2. **Attach event handler:**
   ```powershell
   $previewBrowser.Add_DocumentCompleted({ ... })
   ```
   - `DocumentCompleted` fires when any navigation finishes
   - Including our initial `Navigate("about:blank")`

3. **Event parameters:**
   ```powershell
   param($sender, $e)
   ```
   - `$sender` = The control that fired the event (the WebBrowser)
   - `$e` = Event arguments (not used here)

4. **One-time execution:**
   ```powershell
   if (-not $script:initialPreviewDone) {
       $script:initialPreviewDone = $true
       # ... do work ...
   }
   ```
   - First time: Flag is false → runs → sets flag to true
   - Subsequent times: Flag is true → skips

**Why is the flag needed?**

Without it, this happens:
1. Initial `Navigate("about:blank")` completes → Event fires → Calls `$updatePreview`
2. `$updatePreview` sets `DocumentText` to HTML
3. Setting `DocumentText` internally calls `Navigate()` → Event fires again!
4. Infinite loop! 💥

With the flag:
1. Initial navigation → Event fires → Flag is false → Runs once → Flag set to true
2. Subsequent `DocumentText` changes → Event fires → Flag is true → Skips
3. Perfect! ✅

## 🎨 Advanced Techniques

### Accessing the DOM

You can manipulate the loaded HTML using the DOM:

```powershell
# After HTML is loaded:
if ($browser.Document) {
    # Get an element by ID
    $element = $browser.Document.GetElementById("myElement")

    # Change its content
    $element.InnerText = "New text!"

    # Change its style
    $element.Style = "color: red; font-weight: bold;"

    # Get all links
    $links = $browser.Document.Links
    foreach ($link in $links) {
        Write-Host "Found link: $($link.GetAttribute('href'))"
    }
}
```

### Handling Link Clicks

Prevent navigation and handle clicks yourself:

```powershell
$browser.Add_Navigating({
    param($sender, $e)

    # If URL is not about:blank, cancel navigation
    if ($e.Url.ToString() -ne "about:blank") {
        $e.Cancel = $true
        Write-Host "User clicked: $($e.Url)"
        # Open in external browser:
        Start-Process $e.Url.ToString()
    }
})
```

### Copying HTML to Clipboard

```powershell
$copyButton.Add_Click({
    if ($browser.Document -and $browser.Document.Body) {
        $html = $browser.DocumentText
        [System.Windows.Forms.Clipboard]::SetText($html)
        [System.Windows.Forms.MessageBox]::Show("HTML copied to clipboard!")
    }
})
```

## 🔗 Real-World Application in Signature Manager

Let's trace the complete flow in `Add-WeektoSignature.ps1`:

1. **Control Creation** (line 1822)
   - Browser control instantiated

2. **Initialization** (line 1831)
   - `Navigate("about:blank")` starts async initialization

3. **Event Handler Setup** (line 2582)
   - DocumentCompleted handler attached with one-time flag

4. **Control Creation** (line 2580)
   - `Update-DayControls` creates all dropdown menus
   - Dropdowns get event handlers attached to call `$updatePreview`

5. **Form Display** (line 2587)
   - `$form.ShowDialog()` shows the GUI

6. **Async Initialization Complete** (happens automatically)
   - Browser finishes loading about:blank
   - DocumentCompleted event fires
   - Handler checks flag (false) → runs $updatePreview → sets flag to true

7. **User Interaction** (whenever)
   - User changes a dropdown
   - Dropdown's SelectedIndexChanged event fires
   - Calls `$updatePreview` scriptblock
   - Generates HTML from current selections
   - Sets `browser.DocumentText = $html`
   - Browser renders the updated signature!

**The beauty:** After initialization, updates are instant and synchronous. The async pattern is only needed for the first load.

## ✅ Knowledge Check

### Question 1
Why do we need to call `Navigate("about:blank")`?

<details>
<summary>Show Answer</summary>

To force the WebBrowser control to initialize its internal DOM. Without this, the control exists but can't render HTML. `Navigate()` triggers the creation of the rendering engine.

`about:blank` is used because it loads instantly without network access.

</details>

### Question 2
What would happen without the `$script:initialPreviewDone` flag?

<details>
<summary>Show Answer</summary>

**Infinite loop!**

1. DocumentCompleted fires → Calls $updatePreview
2. $updatePreview sets DocumentText
3. Setting DocumentText internally navigates → DocumentCompleted fires again
4. Goes back to step 2
5. Eventually causes performance issues or crashes

The flag ensures the handler only runs once for initial load.

</details>

### Question 3
When should you use `DocumentText` vs `Navigate()`?

<details>
<summary>Show Answer</summary>

- **Use `DocumentText`** when you have HTML as a string that you want to display
  - Example: Generated HTML, previews, reports

- **Use `Navigate(url)`** when you want to load a web page from a URL
  - Example: Opening a help page, external documentation

In our case, we use both:
- `Navigate("about:blank")` - Initialize the control
- `DocumentText = $html` - Display generated HTML

</details>

### Question 4
Why do we need `ScriptErrorsSuppressed = $true`?

<details>
<summary>Show Answer</summary>

To prevent JavaScript error dialogs from appearing. Since we're displaying HTML signatures (not full web applications), any JS errors would be annoying popups for users.

The signature HTML is simple and shouldn't have scripts, but this property ensures a good user experience even if something unexpected appears in the HTML.

</details>

## 🐛 Common Issues & Solutions

### Issue 1: Blank Page on Load
**Symptom:** WebBrowser shows empty page initially
**Cause:** Trying to set DocumentText before DOM is initialized
**Solution:** Use Navigate("about:blank") + DocumentCompleted event

### Issue 2: Content Doesn't Update
**Symptom:** Setting DocumentText has no visible effect
**Cause:** Trying to set content before control is visible or added to form
**Solution:** Ensure control is added to form before setting content

### Issue 3: JavaScript Errors
**Symptom:** Error dialogs appear when displaying HTML
**Cause:** HTML contains scripts that fail
**Solution:** Set `ScriptErrorsSuppressed = $true`

### Issue 4: Images Don't Load
**Symptom:** `<img src="...">` tags don't show images
**Cause:** Relative URLs don't resolve without a base URL
**Solution:** Use absolute URLs or data URIs (base64 encoded images)
