## 📚 Core Concepts

### What is a PowerShell Script?

A PowerShell script is a plain text file with a `.ps1` extension containing PowerShell commands and logic. Think of it as a recipe - a series of instructions executed in order.

### Anatomy of a Script

Every well-structured PowerShell script has these components:

```powershell
#region 1. HEADER / METADATA
<#
.SYNOPSIS
    Brief description
.DESCRIPTION
    Detailed description
.EXAMPLE
    How to use it
#>
#endregion

#region 2. PARAMETERS (optional)
param(
    [string]$SomeParameter
)
#endregion

#region 3. FUNCTIONS / HELPERS
function Do-Something {
    # Function code
}
#endregion

#region 4. MAIN EXECUTION
# The actual work happens here
#endregion
```

## 🔍 Code Exploration: isScreenLocked

Open the file: `/PSCode/isScreenLocked`

This is the simplest script in our repository - perfect for learning! Let's dissect it:

```powershell
# Detect if the screen is locked
# Returns: $true if locked, $false if unlocked
```

**What's happening here?**
- Lines starting with `#` are **comments** - notes for humans, ignored by PowerShell
- This is the script's header, explaining its purpose

```powershell
function Test-ScreenLock {
```

**Key points:**
- `function` keyword declares a reusable block of code
- `Test-ScreenLock` follows PowerShell naming convention: `Verb-Noun`
- Approved verbs: Test, Get, Set, New, Remove, etc.

```powershell
    $screenLocked = $false
    $processes = Get-Process | Where-Object { $_.ProcessName -eq "LogonUI" }
```

**Breaking this down:**
- `$screenLocked = $false` - Variable declaration and assignment
- `$` prefix indicates a variable
- `Get-Process` - PowerShell cmdlet (command) to list running processes
- `|` - Pipeline operator (passes output of one command to the next)
- `Where-Object` - Filters results
- `{ }` - Scriptblock (code to execute)
- `$_` - Current item in the pipeline
- `.ProcessName` - Property access
- `-eq` - Equals operator

**Translation to English:**
> "Get all running processes and filter to only those named 'LogonUI'"

**Why LogonUI?** When Windows locks the screen, it starts the LogonUI.exe process to show the lock screen.

```powershell
    if ($processes) {
        $screenLocked = $true
        Write-Host "Screen is locked (LogonUI detected)"
        return @{ Locked = $true; Process = $processes[0] }
    }

    Write-Host "Screen is not locked"
    return @{ Locked = $false; Process = $null }
}
```

**Conditional logic:**
- `if ($processes)` - Tests if variable is truthy (has a value)
- `Write-Host` - Outputs text to console
- `return` - Exits function and returns a value
- `@{ }` - Hashtable (key-value pairs)

**Flow:**
1. If LogonUI process found → Screen is locked → Return locked status
2. Otherwise → Screen is not locked → Return unlocked status

**Why return a hashtable?** It returns both the boolean result AND the process object, giving the caller more information.

```powershell
# Export function so it can be used by other scripts
Export-ModuleMember -Function Test-ScreenLock
```

**Module behavior:**
- `Export-ModuleMember` - Makes the function available when this script is imported
- Allows other scripts to use: `. .\isScreenLocked` then call `Test-ScreenLock`

## 💻 Interactive Exercise

Let's experiment with this script in the PowerShell console!

### Step 1: Navigate to the Repository

```powershell
cd C:\Path\To\PSCode
```

### Step 2: Import the Script

```powershell
. .\isScreenLocked
```

**What's that dot-space-dot?**
- `. .\script.ps1` - "Dot-sourcing" - loads the script into your current session
- Without it, functions would only exist inside the script's scope

### Step 3: Call the Function

```powershell
Test-ScreenLock
```

**Expected output:**
```
Screen is not locked

Name                           Value
----                           -----
Locked                         False
Process
```

### Step 4: Examine the Output

```powershell
$result = Test-ScreenLock
$result.Locked          # Access the boolean
$result.Process         # Access the process object (null if unlocked)
```

1. Press `Win + L` to lock your screen
2. Log back in
3. Run `Test-ScreenLock` again
4. Observe the different output

## ✅ Knowledge Check

Test your understanding:

### Question 1
What does this line do?
```powershell
$files = Get-ChildItem -Path C:\Temp | Where-Object { $_.Extension -eq ".txt" }
```

<details>
<summary>Show Answer</summary>

Gets all items in C:\Temp and filters to only show files with .txt extension. The result is stored in the `$files` variable.

</details>

### Question 2
What's the difference between these two?
```powershell
# Option A
.\MyScript.ps1

# Option B
. .\MyScript.ps1
```

<details>
<summary>Show Answer</summary>

- **Option A** (no dot-space): Runs the script in its own scope. Functions defined inside are not available after it finishes.
- **Option B** (dot-space): "Dot-sources" the script into your current scope. Functions remain available after it finishes.

Use Option A for standalone scripts. Use Option B to load utility functions.

</details>

### Question 3
Why do we use `Verb-Noun` naming for functions?

<details>
<summary>Show Answer</summary>

1. **Consistency:** Everyone follows the same pattern, making code predictable
2. **Searchability:** Easy to find commands (`Get-*`, `Set-*`, etc.)
3. **Self-documenting:** The name tells you what it does (`Test-ScreenLock` clearly tests if screen is locked)
4. **Best practice:** PowerShell's built-in cmdlets all follow this pattern

</details>

### Question 4
What does `$_` represent in this context?
```powershell
Get-Process | Where-Object { $_.Name -like "chrome*" }
```

<details>
<summary>Show Answer</summary>

`$_` represents the current object in the pipeline. In this case, it's each process object as it comes through the pipeline. So `$_.Name` accesses the Name property of each process.

</details>

## 🎓 Key Takeaways

✅ PowerShell scripts are `.ps1` text files with commands
✅ Good scripts have: header, parameters, functions, main execution
✅ Functions use `Verb-Noun` naming convention
✅ `#region` / `#endregion` organize code into sections
✅ Comments (`#`) explain the "why", not just the "what"
✅ Variables start with `$`
✅ Pipeline (`|`) passes output between commands
✅ Dot-sourcing (`. .\script.ps1`) loads functions into your session
