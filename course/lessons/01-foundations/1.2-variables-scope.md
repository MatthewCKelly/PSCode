## 📚 Core Concepts

### Variables in PowerShell

Variables are containers that store data. In PowerShell, all variables start with `$`.

```powershell
# Simple assignment
$name = "John"
$age = 30
$isActive = $true

# PowerShell is dynamically typed - you don't need to declare types
$value = 42        # Integer
$value = "text"    # Now it's a string - perfectly valid!
```

### PowerShell Type System

While PowerShell is dynamically typed, it does have types:

```powershell
# Check the type of a variable
$number = 42
$number.GetType().Name    # Output: Int32

# Type casting
[int]$age = "30"          # Converts string to integer
[string]$text = 123       # Converts integer to string
[datetime]$date = "2024-01-15"  # Parses date from string
```

### Common Types

| Type | Example | Description |
|------|---------|-------------|
| `[string]` | `"Hello"` | Text |
| `[int]` | `42` | 32-bit integer |
| `[long]` | `9223372036854775807` | 64-bit integer |
| `[double]` | `3.14` | Floating point number |
| `[bool]` | `$true`, `$false` | Boolean |
| `[datetime]` | `Get-Date` | Date and time |
| `[array]` | `@(1, 2, 3)` | Array of items |
| `[hashtable]` | `@{key="value"}` | Key-value pairs |
| `[pscustomobject]` | `[PSCustomObject]@{Name="John"}` | Custom object |

## 🎯 Understanding Scope

Scope determines where a variable can be accessed. This is **critical** for avoiding bugs!

### Scope Levels

| Scope | Syntax | Visibility | Lifetime |
|-------|--------|------------|----------|
| **Local** | `$variable` | Current block only | Until block exits |
| **Script** | `$script:variable` | Entire script | Until script exits |
| **Global** | `$global:variable` | All scripts/functions | Session lifetime |
| **Private** | `$private:variable` | Current scope only, not children | Until scope exits |

### Example: Scope Bug (Common Mistake!)

```powershell
# Script level
$counter = 0

function Increment-Counter {
    # This creates a NEW local variable, doesn't modify script variable!
    $counter = $counter + 1
    Write-Host "Inside function: $counter"  # Shows 1
}

Increment-Counter
Write-Host "Outside function: $counter"  # Still shows 0! 😱
```

**The Fix:**
```powershell
$script:counter = 0

function Increment-Counter {
    # Explicitly reference script scope
    $script:counter = $script:counter + 1
    Write-Host "Inside function: $script:counter"  # Shows 1
}

Increment-Counter
Write-Host "Outside function: $script:counter"  # Now shows 1! ✅
```

### Real Example from `Add-WeektoSignature.ps1`

Look at lines 844-847:

```powershell
# These variables need to be accessible in scriptblocks (event handlers)
$script:sigPath = Get-OutlookSignaturePath
$script:userAccount = Get-OutlookUserAccount
$script:sigName = $null
$script:existingHTML = ""
```

**Why `$script:`?**

Later in the code (line 1923), inside a scriptblock:

```powershell
$updatePreview = {
    # This scriptblock runs in its own scope
    # Without $script:, it wouldn't see these variables!

    if ($script:existingHTML -match '(?s)<body[^>]*>(.*)</body>') {
        # ...
    }
}
```

**The Problem This Solved:**
- Scriptblocks create their own scope
- Local variables aren't visible inside scriptblocks
- `$script:` makes variables accessible everywhere in the script

### Exercise 2: Arrays

```powershell

$colors = @('Red', 'Green', 'Blue')

# Access elements (zero-indexed)
$colors[0]        # Red
$colors[2]        # Blue
$colors[-1]       # Blue (negative index counts from end)

# Add to array
$colors += 'Yellow'

# Loop through array

    Write-Host "Color: $color"
```

### Exercise 3: Hashtables

```powershell
# Create a hashtable
$person = @{
    Name = "Alice"
    Age = 30
    City = "Seattle"
}

# Access values
$person.Name           # Dot notation
$person['Age']         # Bracket notation

# Add new key
$person.Email = "alice@example.com"
$person['Phone'] = "555-1234"

# Check if key exists
if ($person.ContainsKey('Email')) {
    Write-Host "Email: $($person.Email)"
}

# Loop through hashtable
foreach ($key in $person.Keys) {
    Write-Host "$key : $($person[$key])"
}
```

### Pattern 3: Strongly-Typed Parameters

From `Test-LiquidFilesAccess.ps1`:

```powershell
function Test-API {
    param(
        [Parameter(Mandatory)]
        [ValidateNotNullOrEmpty()]
        [string]$ApiKey,

        [Parameter()]
        [ValidateRange(1, 100)]
        [int]$MaxResults = 10,

        [Parameter()]

    # Type safety prevents bugs!

```

### Pattern 4: Array Building

```powershell
# Slow way (creates new array each time)
$results = @()
foreach ($item in $items) {
    $results += Process-Item $item  # ❌ Slow for large arrays
}

# Fast way (collect pipeline output)
$results = foreach ($item in $items) {
    Process-Item $item  # ✅ Fast - collects all output
}

# Or use pipeline
$results = $items | ForEach-Object { Process-Item $_ }
```

## ✅ Knowledge Check

### Question 1
What's wrong with this code?

```powershell
$count = 0

function Add-One {
    $count = $count + 1
}

Add-One
Add-One
Write-Host $count  # Expects 2, gets 0
```

<details>
<summary>Show Answer</summary>

The function creates a local `$count` variable instead of modifying the script-level one. Fix:

```powershell
$script:count = 0

function Add-One {
    $script:count = $script:count + 1
}
```

Or use the `$script:` prefix consistently.

</details>

### Question 2
What's the output?

```powershell
$array = @(1, 2, 3)
$array[1]
```

<details>
<summary>Show Answer</summary>

Output: `2`

Arrays are zero-indexed:
- `$array[0]` = 1
- `$array[1]` = 2
- `$array[2]` = 3

</details>

### Question 3
What type is `$result`?

```powershell
$result = "10" + "20"
```

<details>
<summary>Show Answer</summary>

Type: `String`
Value: `"1020"`

When both operands are strings, PowerShell concatenates them. To do math:
```powershell
$result = [int]"10" + [int]"20"  # Result: 30 (integer)
```

</details>

### Question 4
How do you create an empty array vs empty hashtable?

<details>
<summary>Show Answer</summary>

```powershell
# Empty array
$array = @()

# Empty hashtable
$hashtable = @{}

# They look similar but behave differently!
```

</details>

## 🎓 Key Takeaways

✅ Variables start with `$`
✅ PowerShell is dynamically typed but supports type casting with `[type]`
✅ Arrays use `@()`, hashtables use `@{}`
✅ **Scope is critical:** Use `$script:` for variables accessed in scriptblocks/functions
✅ Arrays are zero-indexed
✅ Hashtables can use dot notation or bracket notation
✅ `+=` for arrays is slow for large collections
✅ Type casting prevents bugs: `[int]$age = "30"`
